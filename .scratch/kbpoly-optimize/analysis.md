# Optimizing the polynomial Kaiser-Bessel window against the transform error

Status: analysis, no implementation. Prototype scripts in this directory
(`kbopt.py`, `kbopt2.py`, `kbopt3.py`; run with
`uv run --with numpy --with scipy python kbopt.py [sigma m]`), raw output in
`results/`.

## 1. Verdict

The idea is sound and the room is real but bounded. Once the window is a
per-cell polynomial, the transform's error is an explicit, cheap, linear
functional of the polynomial coefficients (section 3), and the coefficients can
be chosen to minimize that functional directly instead of reproducing the
Kaiser-Bessel function. There are two separate levers, and the first is free:

1. **Pick the degree from the measured transform error, not from the Chebyshev
   tail.** The table rule (`2 sum_{j>d} max_cells |c_j| <= 0.05 pi e^(-bR)`)
   is a bound that adds the per-cell truncation errors without phase
   cancellation. Measured against the actual aliasing functional, the current
   Chebyshev fit already matches the truncated Kaiser-Bessel window 1 to 4
   degrees below the table degree (section 6, column "chebKB reaches KB").
   No change to the fit, only to the generator.
2. **Fit the coefficients to the error functional.** At the table degree, a
   weighted least-squares fit lowers the RMS error by 1.3x to 3.1x and the
   worst-case error by about 1.3x to 4x over the six cases measured, at
   identical run-time cost, with no growth of the monomial coefficients. A
   minimax (Lawson) fit lowers the worst-case error by 3.4x to 8x in the three
   cases checked on a dense sample grid, at some cost in RMS error; it is
   only trustworthy on a dense grid (section 6.2).

Re-optimizing the deconvolution factors gains nothing measurable beyond the
library's closed-form `I0` scaling, so `PHI_HUT` stays as it is. The gains are
constant factors: with the reach `R = m + 1` fixed, the truncated
Kaiser-Bessel window is already within a small factor of the optimal
2m+2-tap kernel, which is the known result of Fessler and Sutton (2003), and
the `e^(-bR)` rate is set by the support, not by the fit.

Recommended route, in order: regenerate the degree table from the error
functional (lever 1); replace the Chebyshev interpolation in `Y(kb_poly_fit)`
by a regularized weighted least-squares fit (lever 2, closed form,
microseconds); treat a bounded Lawson iteration for the worst-case objective
as an optional third step once the generator can certify it.

## 2. What the branch does today

`Y(kb_poly_fit)` (`kernel/util/kbpoly.c`) interpolates the Kaiser-Bessel
window with reach `R = m + 1` on each unit cell of the window argument at
`deg + 1` Chebyshev points, converts to monomials in the cell offset `t`, and
applies one refinement step against the run-time Horner evaluator. The degree
comes from `kernel/util/kbpoly_data.h`, generated by `tests/kbpolygen`, as the
smallest `d` whose Chebyshev tail, summed over all cells, is below 5 percent of
the transform's own aliasing error `pi e^(-bR)` or below `eps`.

The deconvolution is unchanged: `PHI_HUT` is `I0(R sqrt(b^2 - w^2)) / I0(R b)`,
the Fourier transform of the entire sinh/sin function, not of the window the
transform actually uses. The window the transform uses is, per node with offset
`t = frac(n x)`, the 2m+2 taps `psi(a + t)` for cells `a = -R .. R-1` (the
NFFT anchors below the node, `uo()` in `kernel/nfft/nfft.c`), which is the
sinh branch truncated at its support edge `|y| = R`, where it does not vanish.

So the fit targets the *function* with a tolerance expressed in the *transform*
error. The polynomial is a faithful copy of a window that is itself only
near-optimal, and the degree pays for a faithfulness the transform does not
need.

## 3. The exact error functional of a grid-aligned piecewise polynomial window

In grid units `y = n x`, offset `t = frac(y)`, cells `a = -R .. R-1`, write the
window as `psi(a + t) = p_a(t)`. For frequency `k` with `xi = k / n`, the NFFT
reproduces `e^(2 pi i k x)` with the relative error

    E(xi, t) = D(xi, t) / C(xi) - 1,
    D(xi, t) = sum_a p_a(t) e^(-2 pi i xi (a + t)),

where `C(xi)` is the deconvolution factor (today `PHI_HUT`). `D` is the
one-point-per-cell quadrature of `psi_hat(xi)` at offset `t`; by Poisson
summation `D(xi, t) = sum_r psi_hat(xi + r) e^(2 pi i r t)`, so with
`C = psi_hat` the error is the familiar aliasing sum over `r != 0`. The error
measures are

    worst case  J_inf = max over |xi| <= 1/(2 sigma), t in [0,1) of |E|,
    RMS         J_2   = sqrt(mean |E|^2)  (uniform in xi and t, or weighted),

bounding the transform error for `f_hat` in the unit l1 and l2 ball. The
prototype reproduces the known Kaiser-Bessel constant through this formula
(`J_inf / (pi e^(-bR))` lands inside the `c` range `[1.10, 2.81]` the generator
documents). For `d > 1` the per-axis errors add to first order, so the per-axis
functional is the right design target.

Three consequences matter for the design:

1. `D` is **linear** in the coefficient vector, so `E` is affine for fixed `C`.
   Every objective below is a linear least-squares or a linear minimax problem
   in a few dozen to a few hundred unknowns. No transform needs to be run.
2. The error at offset `t` depends only on the 2m+2 cell polynomials evaluated
   at the **same** `t`. This is why the Chebyshev tail adds up over the cells
   in the table rule: by Euler-Maclaurin, a jump of the window across a cell
   boundary enters `E` at first order with weight `B_1(t) = t - 1/2`. The rule
   is a bound, though; the phases `e^(-2 pi i xi a)` cancel much of the sum,
   which is where lever 1 comes from.
3. Everything is closed form: `psi_hat` of a polynomial cell is a finite sum
   of spherical Bessel functions, or a `d + 10` point Gauss-Legendre rule, and
   the metrics are a few matrix products. The whole functional for one
   `(sigma, m, d)` costs well under a millisecond in C.

## 4. The design problem

Unknowns: Chebyshev (or Legendre) coefficients per cell, `(2m + 2)(d + 1)`;
evenness `p_{-1-a}(1 - t) = p_a(t)` halves them. Optional linear constraints:
continuity across cells, normalization `C(0) = 1`. Objectives:

- **l2**: minimize `sum over (xi, t) samples of w |E|^2`. A weighted linear
  least-squares problem. The weights can be the uniform measure, the empirical
  distribution of the plan's node offsets `frac(n x_j)`, or a spectral prior.
- **worst case**: minimize `max |E|` over the band and the offsets. A linear
  Chebyshev (minimax) problem with complex residuals, a second-order cone
  program in general.
- **free deconvolution**: `C(xi)` as additional unknowns. For the l2-in-`t`
  objective the optimal `C` per `xi` is closed form, `1/C = psi_hat(xi) /
  sum_r |psi_hat(xi + r)|^2`, which gives the classical per-frequency error
  `sum_{r != 0} |psi_hat(xi+r)|^2 / sum_r |psi_hat(xi+r)|^2` of Nieslony and
  Steidl and of Jacob. Alternating `p` and `C` is a block coordinate descent on
  a nonconvex but benign problem.

Continuity is not needed: the optimized windows have interior jumps of the
same order as the error (section 6.3) and use them. The run-time cost is
unchanged by all of this: the coefficient table has the same shape, `PHI_RUN`
and `kb_poly_phi` do not change. Only the plan-time fit and the degree rule
change.

## 5. Algorithms, in order of recommendation

### 5.1 Weighted least squares (l2 objective, and a good worst-case proxy)

Normal equations or a QR of the stacked real/imaginary design matrix. With
evenness, `n_u = (m + 1)(d + 1) <= 120` unknowns in double, and about `40 xi
x 32 t` samples. The Gram matrix has structure: it is block-Toeplitz in the
cell index (the `xi` integral of `e^(-2 pi i xi (a - a'))` over the band,
weighted by `1/|C|^2`, depends on `a - a'` only) with `(d+1) x (d+1)`
polynomial blocks, so it is assembled in `O(n_xi (2m+2) (d+1)^2)` and solved
densely in `O(n_u^3)`, microseconds. Solve in the Chebyshev basis and convert
to monomials with the existing `cheb_to_monomial` and refinement step; never
set up the problem in the monomial basis.

Regularize toward the Chebyshev interpolant of Kaiser-Bessel: minimize
`J_2^2 + lambda |a - a_KB|^2`. At the degree the table picks the problem is
well posed, but one degree above it the extra coefficients are not determined
by the error functional, the Gram matrix becomes rank deficient and an
unregularized solve picks large coefficients (the minimax runs in section 6
show monomial growth of 5x to 32x once over-provisioned). With the
regularization the fit degrades gracefully to today's fit and is continuous
in `sigma`. This variant alone gives the 1.3x to 3.1x RMS gains, deterministic, no
iteration, no tuning. Its worst-case gain (1.3x to 4x) is a by-product and
moves by 20 to 30 percent with the sample grid, since the objective does not
see the maximum.

### 5.2 Lawson iteratively reweighted least squares (worst-case objective)

Lawson's algorithm (1961) reaches the discrete Chebyshev solution of a linear
minimax problem by repeated weighted least squares with weights
`w_i <- w_i |r_i| / sum w |r|`. It handles complex residuals directly, needs no
derivative information, and reuses the solver of 5.1. Convergence is linear
and can stall on degenerate problems; the modern treatments (Nakatsukasa and
Trefethen 2020, Filip, Nakatsukasa, Trefethen and Beckermann 2018, where it is
the polish step of AAA-Lawson) give the practical safeguards: keep the best
iterate and cap the iteration count. The prototype shows the gain over least
squares is reached within 5 to 20 iterations (section 6.2).

The catch is discretization. A minimax solution exploits the gaps of the
sample grid: on the `40 x 32` grid the exact discrete optimum is 10 to 60
percent *worse* on a fine grid than it is on its own grid, and at larger `m`
the coarse-grid Lawson result is no better than least squares. A `120 x 96`
grid fixes this (section 6.2): the Lawson iterate's fine-grid error is then
within 1 to 3 percent of its design-grid maximum, 20 iterations are enough,
and the problem is still tiny (11520 complex samples, under 100 unknowns). An
exchange step that adds the fine-grid maxima of `|E|` to the sample set and
re-solves would get there with fewer samples, since the error surface is
smooth in `xi` and polynomial in `t`. Either way the generator must certify
the choice (5.3), which is why 5.1 goes first.

### 5.3 Exact linear minimax solvers (offline only)

The same problem as an LP with a polygonal approximation of the complex
modulus (HiGHS solves the 20k-constraint, 100-unknown instance in seconds) or
as an SOCP (Clarabel, ECOS, MOSEK). Useful in the generator to certify what the
plan-time Lawson loop leaves on the table, not for the plan itself. A
multivariate Remez exchange on the `(xi, t)` domain is possible because the
error surface is smooth and the active set is small, but the exchange step is
not guaranteed to converge in two variables, so LP/SOCP is the safer offline
tool.

### 5.4 Free deconvolution factors

Alternate 5.1 or 5.2 with the closed-form `C` above, or parametrize `C` as the
closed-form `I0` factor times a low-degree even polynomial in `xi`, as Fessler
and Sutton did with a short cosine series for their scaling factors. The
prototype shows no measurable gain over the library's `I0` factor at any degree
(columns `chebKB*` and `LS*` in section 6), which agrees with their finding
that Kaiser-Bessel's own Fourier scaling is close to the min-max optimal
scaling. Not recommended; it would also force the `PRE_PHI_HUT` table on every
plan.

### 5.5 Designing a continuous kernel and then fitting it

The literature's optimal kernels are continuous objects: Fessler and Sutton's
per-offset min-max interpolator (for each `t`, a `(2m+2) x (2m+2)` linear
system with a Toeplitz matrix built from the band), Nieslony and Steidl's
least-squares optimal window, Jacob's optimized least-squares NUFFT, and the
prolate spheroidal wave functions as the l2 concentration optimum. One could
fit any of these per cell with the current Chebyshev machinery. This is
inferior to 5.1 and 5.2 because it spends degrees reproducing the continuous
optimum, exactly the inefficiency this analysis is about; the right space to
optimize in is the space of implementable kernels, the degree-`d` cell
polynomials. The per-offset exact solve is however the tool of choice for the
special case in 5.7.

### 5.6 Degree selection

The table rule becomes: smallest `d` such that the fitted `J_inf` (or `J_2`)
is within a factor `(1 + eta)` of its limit for `d -> infinity`, or below the
precision floor. For lever 1 alone, the fit is today's Chebyshev interpolant
and the limit is the truncated Kaiser-Bessel error; for lever 2 it is the
least-squares optimum. The generator needs `numpy` (and the LP of 5.3 for
certification), a few minutes per format on the current `sigma` grid, in place
of the `mpmath` Chebyshev tails. The monotonicity-in-`sigma` check the
generator already does carries over, with one caveat: the optimized error is
not guaranteed monotone in `d` on a coarse grid (section 6.2), so the
generator should evaluate every candidate degree, not bisect.

### 5.7 Node-adaptive weighting (optional extension)

The plan knows its nodes. Weighting the `t` samples by the histogram of
`frac(n x_j)` costs nothing in 5.1 and gives an l2 error tailored to the data.
In the degenerate case of few distinct offsets (shifted grids, polar grids with
offsets constant along rays), the problem per offset is Fessler and Sutton's
exact min-max interpolator and the error drops by orders of magnitude, not a
constant factor. This is a separate feature; it is noted here because the same
functional and solver serve it.

## 6. Prototype measurements

Prototype: `numpy` in double, Chebyshev basis per cell, design grid `40 xi x 32
t`, metrics on a `160 x 160` grid; Lawson with 120 iterations, best iterate
kept. "KB" is the truncated Kaiser-Bessel window with the library's `C`, the
quantity the table rule targets. Degrees are the double-precision table
degrees. Full tables in `results/`.

### 6.1 At the table degree

| sigma, m | table d | KB J_inf | KB J_2 | chebKB reaches KB at d | LS gain J_inf | LS gain J_2 | LS beats KB from d | Lawson gain J_inf |
|---|---|---|---|---|---|---|---|---|
| 2, 2 | 7 | 2.59e-5 | 4.33e-6 | 6 (5 is 12% above) | 1.6x | 1.44x | 6 | 3.4x (dense grid, d = 6) |
| 2, 3 | 9 | 3.13e-7 | 4.84e-8 | 7 | 2.6x | 1.45x | 7 | 3.5x (dense grid, d = 7) |
| 4, 2 | 9 | 2.17e-6 | 3.62e-7 | 5 | 4.3x | 3.1x | 5 | 8.2x (dense grid, d = 6) |
| 1.5, 4 | 9 | 2.57e-7 | 2.27e-8 | 8 | 3.0x | 1.27x | 8 | 2.7x (coarse grid) |
| 2, 5 | 12 | 7.98e-11 | 6.38e-12 | 10 | 3.8x | 1.40x | 10 | 4.6x (coarse grid) |
| 1.25, 6 | 11 | 3.87e-8 | 4.08e-9 | 9 | 1.6x | 1.35x | 9 | 2.0x (coarse grid) |

Reading the columns: "chebKB reaches KB at d" is lever 1, the degree at which
today's fit already matches the truncated Kaiser-Bessel error within 5 percent
when that error is measured rather than bounded. "LS gain" is lever 2 at the
table degree; "LS beats KB from d" is the smallest degree at which the
least-squares fit is already below the Kaiser-Bessel error, so the two levers
stack: the same error as today's table at 1 to 4 degrees less, or the gain
at the same degree. The LS worst-case gains are from the `40 x 32` grid and move by 20 to 30
percent with the grid (6.2); the RMS gains do not. The free-deconvolution
variants `chebKB*` and `LS*` are within 3 percent of their fixed-`C`
counterparts in every case. The coarse-grid Lawson figures are lower bounds
on the gain, see 6.2.

The gains are largest where the Kaiser-Bessel window is least suited to the
band: at `sigma = 4` the band is narrow and Kaiser-Bessel's `b` cannot exploit
that, the least-squares fit can.

### 6.2 Minimax: what the discretization costs

`kbopt3.py`, design grid `120 x 96`, metrics on `240 x 240`, degree one
below the table degree. "design max" is the maximum of `|E|` over the design
grid, "fine" the metric on the fine grid; the gap between them is what the
discretization costs.

| sigma, m, d | KB J_inf | LS fine J_inf / J_2 | Lawson 5 it. | Lawson 20 it. | Lawson 60 it. (design max / fine J_inf / J_2) | LP exact on design grid (design / fine) |
|---|---|---|---|---|---|---|
| 2, 2, 6 | 2.59e-5 | 1.97e-5 / 2.90e-6 | 7.73e-6 | 7.60e-6 | 7.37e-6 / 7.54e-6 / 4.52e-6 | 7.33e-6 / 7.77e-6 |
| 2, 3, 7 | 3.13e-7 | 1.78e-7 / 3.17e-8 | 9.95e-8 | 8.89e-8 | 8.11e-8 / 8.91e-8 / 5.88e-8 | (not run to completion) |
| 4, 2, 6 | 2.17e-6 | 5.77e-7 / 1.15e-7 | 2.72e-7 | 2.67e-7 | 2.66e-7 / 2.66e-7 / 1.48e-7 | 2.48e-7 / 3.35e-7 |

Three observations. First, on the dense grid Lawson converges in 5 to 20
iterations to a solution whose fine-grid error is within 1 to 3 percent of
its design-grid maximum, and 2 to 2.3x below the least-squares worst case
(3.4x to 8.2x below Kaiser-Bessel). Second, the exact discrete optimum from
the LP is lower on the design grid but *higher* on the fine grid (35 percent
at `sigma = 4`): a vertex solution of the discretized problem generalizes
worse than Lawson's weighted least-squares iterate, so the plan-time
algorithm of choice is Lawson on a dense grid, and the LP serves only as a
lower bound in the generator. Third, the minimax fit pays for its worst case
with RMS: its `J_2` is 1.3x to 1.9x above the least-squares `J_2`, and at
the table degree it is about at Kaiser-Bessel's `J_2`. Which objective to
ship is a policy choice; the l1-ball worst case is what the library's bounds
and tests speak about, which argues for minimax at the degree the table picks
and least squares as the fallback.

### 6.3 Window shape

The optimizer does not make the window continuous and does not remove the
support-edge jump of the truncated Kaiser-Bessel window: at `sigma = 2, m = 2,
d = 6` the edge value stays at about `2e-5` of the peak for every fit and the
interior cell-boundary jumps grow from the Chebyshev truncation level
(`9e-7`) to `1.5e-5` (least squares) and `3e-5` (minimax), all relative to
the peak, while the fitted window departs from Kaiser-Bessel by up to `7e-5`
of the peak in the central cells. The error functional sees the window only
through `D(xi, t)`, and jumps are cheap there. Continuity constraints would
cost error for nothing, unless one wants the single-point evaluator
`kb_poly_phi` to be continuous for other consumers (`PRE_LIN_PSI`).

## 7. Fitting this into the codebase

- `Y(kb_poly_fit)` keeps its signature and its monomial conversion and
  refinement step; the Chebyshev interpolation at the front becomes the
  regularized LS solve of 5.1, with an optional Lawson loop (fixed iteration
  count, chosen per precision like `KB_POLY_DEG_MAX`). `Y(kb_poly_degree)`
  reads a regenerated `kbpoly_data.h`.
- Do the solve in double (or `E`) even in the float build: a float LS with
  100 unknowns loses about three digits, and the float target is `1e-7`
  relative. The result is rounded to `R` once, as the current fit already is
  via the refinement step.
- The window is then defined by its stencil. The NFFT touches cells
  `-R .. R-1` only; `KB_POLY_COLS(m) = 2m + 4` keeps two outer cells for the
  other anchorings and `PRE_LIN_PSI`. For an optimized window those outer
  cells are zero by construction, and each module's fit must use that
  module's stencil. Today every module reads the same function, so nothing
  has to agree; after this change the table is stencil-specific.
- `tests/window.c` compares the polynomial window against Kaiser-Bessel
  reference values. Those comparisons become meaningless and must be replaced
  by a check of the error functional itself (`J_inf` against the regenerated
  table's target). The transform tests' bounds stay valid, since they are upper
  bounds and the error only falls, but the accuracy report will show a step.
- Reproducibility: the fit is deterministic given the sample grids, the
  regularization and the iteration cap, but the result now depends on
  floating-point details of the solve. The generator should run the same
  algorithm in double and certify the table against the LP optimum, so that a
  plan-time fit on any platform meets the table's target with margin.

## 8. Risks and limits

- The achievable gain is a constant factor: 1.3x to 3x in RMS (least
  squares) or 3x to 8x in the worst case (minimax) at fixed `(sigma, m)`,
  or 1 to 4 degrees. The `e^(-bR)` rate is set by the support and does not
  move.
- The optimized error is equiripple across the band rather than peaking at
  `|k| = N/2` as Kaiser-Bessel's does, so error figures on specific inputs
  move by different factors than `J_inf` does.
- Over-provisioned degrees are ill-posed for the optimized fit; the
  regularization of 5.1 is not optional.
- Plan-time cost: 5.1 is negligible; a 20-iteration Lawson loop at `m = 11`,
  `d = 12` is on the order of ten milliseconds per axis in C, acceptable, but
  it should be measured against the rest of plan initialization and made
  skippable (the `ANALYTIC_WINDOW` flag already provides the fallback).
- The minimax solution is less smooth across cells than the Chebyshev
  interpolant; the prototype found no growth in the monomial coefficients at
  the table degree, but the generator should keep the per-precision
  degree-cap measurement in place.
